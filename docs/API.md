# API contract

Base URL: `http://localhost:4000` in development. Production requires HTTPS. JSON request/response, UTC ISO 8601 dates, ISO 4217 currencies, safe integer minor units. Authenticated routes use `Authorization: Bearer <accessToken>`. The server derives the actor exclusively from the validated session.

Schemas are executable in `packages/contracts/src/index.ts`; the mobile API repository imports the corresponding TypeScript types. Core request types are `CreateTransaction`, `CreateSettlement`, `CreateGoal`, and `CreateShare`. Errors return `{code, message}`, with 400 validation/domain error, 401 invalid session, 403 forbidden action, 404 inaccessible resource, 409 concurrent/idempotency conflict, 429 rate limit, or 503 provider unavailable. Internal failures return a redacted message and request ID.

## Sessions

| Route                  | Purpose                              | Boundary                                          |
| ---------------------- | ------------------------------------ | ------------------------------------------------- |
| POST `/auth/otp`       | `{phone}` → challenge ID, expiry     | 6/IP/15 minutes; 4/phone/15 minutes               |
| POST `/auth/verify`    | `{challengeId, code}` → `Session`    | 5 attempts/challenge, 5-minute expiry, single use |
| POST `/auth/refresh`   | `{refreshToken}` → rotated `Session` | Old token reuse revokes its family                |
| POST `/auth/logout`    | Revoke active session                | Authenticated session only                        |
| GET `/sessions`        | List active sessions                 | Current account only                              |
| DELETE `/sessions/:id` | Revoke a session                     | Current account only                              |

Access tokens last 10 minutes. Refresh tokens are random and only SHA-256 digests are stored. Every authenticated request also checks the database session and soft-deleted account, so revocation is immediate rather than waiting for JWT expiry. OTP digests use HMAC with a separate pepper.

## Financial records

| Route                            | Purpose                                                              | Authorization                                                                               |
| -------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| GET `/dashboard`                 | Account, accessible transactions/ledgers/debts, own tags/goals/peers | Owner, participant, or active ledger member                                                 |
| POST `/transactions`             | Create expense, shared expense, loan, personal incoming adjustment   | Author = current user; active ledger members; own active tags                               |
| POST `/settlements`              | Append repayment and allocations                                     | Current user must be debtor; creditor must be an active ledger member                       |
| POST `/transactions/:id/actions` | Complete, reverse, dispute, resolve                                  | Version check; author controls complete/reverse; participant opens dispute; opener resolves |
| GET `/transactions/:id/history`  | Auditable changes                                                    | Same row-level access as transaction                                                        |
| GET `/analytics`                 | Range-filtered analytics                                             | Account-scoped projection                                                                   |

Example shared expense:

```json
{
  "idempotencyKey": "11111111-1111-4111-8111-111111111111",
  "title": "Shared lunch",
  "amountMinor": 10000,
  "currency": "INR",
  "type": "SHARED_EXPENSE",
  "status": "SETTLED",
  "occurredAt": "2026-09-09T08:00:00.000Z",
  "ledgerId": "20000000-0000-4000-8000-000000000001",
  "splitMethod": "EQUAL",
  "participants": [
    { "userId": "10000000-0000-4000-8000-000000000001" },
    { "userId": "10000000-0000-4000-8000-000000000002" },
    { "userId": "10000000-0000-4000-8000-000000000003" },
    { "userId": "10000000-0000-4000-8000-000000000004" }
  ],
  "tagIds": []
}
```

For `EXACT`, participant `value` is minor units. For `PERCENTAGE`, it is integer basis points totaling 10,000. For `SHARES`, it is a nonnegative integer weight. Stored totals and obligations are generated by the server. Clients cannot supply arbitrary obligations. A loan requires a distinct borrower, ledger, and `PENDING_LOAN` status. A personal incoming `ADJUSTMENT` must be settled and outside a shared ledger; destination is derived as the signed-in account.

Settlements require `{idempotencyKey, ledgerId, debtorId, creditorId, amountMinor, currency, reference?}`. The server allocates to eligible oldest pairwise obligations, rejects overpayment, and writes everything atomically. A duplicate key with the same normalized payload returns the original record; changed content returns 409. Do not generate a new key when retrying an uncertain submission.

Action body: `{action: "complete" | "reverse" | "dispute" | "resolve", version, reason}`. A dispute prevents its underlying obligations from being repaid. Resolving restores the prior status; monetary corrections then require reversal/replacement. Reverse repayments before reversing an expense that they reduced.

Analytics query: `start`, `end`, `currency`, optional `zone`, `ledgerId`, `tagId`, `peerId`, `type`, `status`. Ranges are `[start, end)`; presets are calculated in the chosen IANA zone. Shared expense spending uses the account's own split. Loans and settlements count as cash flow but not spending. Current debt totals are labeled current, not falsely presented as historical as-of balances. Tagged category totals can overlap.

## Imports, sharing, and receipts

Native SMS review does not upload raw messages. `/imports/handled` supports GET and POST (`{fingerprint,decision}`), is account-scoped, and expires fingerprints after seven days. Local parsing creates no financial record; only acceptance invokes the ordinary idempotent transaction endpoint.

`POST /shares` takes start/end/currency, optional ledger/tag scope arrays, `includeTransactions`, `showDescriptions`, optional `recipientPhone`, and `expiresInHours` (1–168, default 24). It returns `{id,url,expiresAt}`. `GET /shares` lists the owner's links without raw bearer tokens. `DELETE /shares/:id` revokes an owned link. `GET /shared/:token` is public only when the link is public; private links require authentication. The API always checks expiration immediately, independently of worker availability. The link token is never stored or logged in clear text.

Attachments:

1. `POST /transactions/:id/attachments` with `{contentType,size}` returns `{id,uploadUrl}`. Only the original author can attach.
2. PUT the selected bytes to that signed URL, using the declared content type.
3. `POST /attachments/:id/complete` checks the scanning verdict. Pending files remain quarantined.
4. `GET /transactions/:id/attachments` lists metadata visible to authorized ledger viewers.
5. `GET /attachments/:id/download` issues a 60-second read URL only for ready, authorized files.

Development storage accepts JPEG/PNG/PDF magic bytes and writes private local files with exclusive creation. It is a development validation mock, not a malware scanner. The production gateway must validate content independently, scan it, constrain signed upload size/type and prevent object replacement.

## Optional expense items

`POST /transactions` accepts `items?: {name, quantity, amountMinor}[]` for personal and shared expenses only. Up to 100 lines; names are 1–120 characters; quantity is positive with up to three decimals; signed line totals use integer minor units. When nonempty, line totals must equal `amountMinor`, including tax and discount lines. Item data participates in the existing request digest and serializable insert. `/dashboard` includes ordered `items` only on transactions visible to the authenticated account. Existing clients may omit items.
